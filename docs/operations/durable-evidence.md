# Durable review evidence

Application evidence is saved to authenticated Convex file storage before a sandbox write is accepted. Text artifacts and binary GitHub artifact archives survive loss of the native workflow or VM. Reads of managed files use durable storage as their authority and hydrate the local sandbox, including after a remote commit succeeded but the local write failed.

Each artifact has a signed binding containing the repository node ID, repository name, PR, base, head, patch fingerprint, review policy digest and execution attempt ID. Its original root session and artifact path also participate in authentication. The evidence signing key remains in the application runtime; neither repository sandboxes nor Convex receive it. Convex uses the existing authenticated memory service endpoint and token.

A new execution attempt can recover only from the predecessor selected by the lifecycle service. Immutable artifact-set records retain these predecessor links even after the mutable delivery record moves to its next attempt. The reader checks every predecessor binding and original HMAC before saving a newly signed copy under the new root. Cycles, mismatched identity, missing blobs and transient storage errors fail closed. Individual files are authenticated on use; a saved lane is reused only after the workflow separately validates its checkpoint, evidence manifest, packet progress and requirements.

The lifecycle eligibility probe checks signed preparation, checkpoints and application packet progress using paginated listings and bounded parallel reads. It does not download all patch or archive blobs. Its progress digest ignores root identifiers, signing wrappers, preparation timestamps, checkpoint revision-only changes, next-step wording and limitations. A signed empty admission receipt can support recovery before preparation only when durable native Gateway telemetry proves every recorded request was rejected for authentication or payment before any generation. Missing telemetry, unfinished requests, generated output, generation IDs and positive usage do not establish that proof. This admission check is not a claim that historical billing has been reconciled.

The authenticated service exposes `POST /review-artifacts/put`, `/get`, `/metadata` and `/list`; these are operational application APIs, not model tools. All require `KNOWN_GOOD_REVIEW_MEMORY_TOKEN`. Artifact blobs retain the latest accepted path version; checkpoint revisions cannot move backward or change content at the same revision. Storage failures remain visible and must be repaired before review work continues.

Offline tests cover tampering, wrong scope and policy, superseded writes, repeated transport requests, sandbox loss, a failed local write after durable commit, and multi-attempt recovery chains. They do not certify hosted storage availability or measured paid-run savings.

Before replacement after terminal root failure, native descendant reconciliation enumerates canonical workflow storage by its persisted Eve and Workflow lineage attributes. This includes pending children that have not reached their first heartbeat. It signals discovered child sessions, cancels their exact native runs, then scans again to catch children created during cancellation. New recovery work is admitted only after every discovered run is terminal. Retained child IDs with missing or unrelated lineage, incomplete pagination, and cancellation or lookup failures remain errors.

This is a native scheduling fence, not a claim that an already-running provider HTTP request has physically stopped. The installed runtime rejects new steps on terminal runs but allows existing running steps to record their outcomes. Public APIs provide no authoritative executor lease-expiry proof for a running step left behind by a crashed process. Reconciliation therefore reports those step IDs explicitly; application ownership checks must reject subsequent provider calls from the old attempt, and any outstanding request remains subject to cost reconciliation. No timeout fabricates completion or zero cost.
