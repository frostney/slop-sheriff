## Findings and remediation

- **CA-1 / BLOCKING / BEHAVIOR, fixed:** `src/github/inbound.ts:66` and
  `src/github/publication.ts:872` accepted state markers without author checks.
  A contributor's copied or fabricated state could become a baseline; marker
  copying also selected other authors' comments for updates. Shared ownership
  validation now checks GitHub Bot authors and the configured immutable bot ID,
  falling back to the already configured `known-good-review[bot]` login.
  Missing identity and invalid configured IDs fail closed. Tests cover forged
  admission, copied state writes, and timeline/inline marker isolation.
- **CA-2 / IMPORTANT / BEHAVIOR, fixed:** `src/models/routing.ts:45` scanned all
  history and used the last envelope. A copied envelope in a patch, tool result,
  or later message could reroute a lane and its probe-window classification.
  Only the initial delegation's anchored envelope is now authoritative.
- **CA-3 / IMPORTANT / BEHAVIOR, fixed:** `src/models/routing.ts:127` treated
  continuation numbers as model-chain indexes. Attempt one exhausted a scalar
  model chain; longer chains silently changed models before failing. Every fresh
  continuation now starts with the configured primary and complete Gateway
  fallback chain. Attempts remain continuation metadata.
- **CA-4 / IMPORTANT / BEHAVIOR, fixed:**
  `src/review/prepare-review-evidence.ts:68` rejected source spelling reserved
  tokenizer delimiters, such as `<|endoftext|>`, before review. Delimiters are
  now ordinary source text. The same tokenizer instance serves warm reviews,
  and the lite entry avoids bundling unused ranks.
- **CA-5 / IMPROVEMENT / QUALITY, fixed:**
  `agent/tools/read_review_evidence.ts:98` validated the ledger, capabilities,
  and artifact archives before delegating to a function that repeated the same
  work. Packet reads now use that function's single validation path. Direct
  tool tests prove one ledger/capability read and continued corruption rejection.
- **CA-6 / IMPROVEMENT / QUALITY, fixed:** `agent/instructions.md:1` repeated
  workflow and state-ownership rules on every model call;
  `agent/channels/github.ts:563` also sent unchanged findings and old report
  metadata. The prompt is shorter with the same coverage, authority, recovery,
  and publication obligations. Dispatch contains selected findings only.
- **CA-7 / IMPORTANT / QUALITY, fixed:** Revalidation exposed `z.unknown()`
  while execution required canonical findings. The input now uses the canonical
  array schema with a 100-finding bound. The actual AI SDK-generated JSON Schema
  covers all four finding variants. This deliberately overlaps PR #35.

## Third pass: trust, concurrency, and failure recovery

- **CA-14 / BLOCKING / BEHAVIOR, fixed:** An actor controlling sandbox files could
  rewrite evidence and its hashes together. Application text artifacts now carry
  HMAC-SHA256 authentication bound to their root session and exact path. The key
  stays in the app; binary archives remain bound by the authenticated ledger.
- **CA-15 / IMPORTANT / BEHAVIOR, fixed:** Compaction could remove the delegation
  used for routing, and tools accepted a caller-selected lane axis. Eve session
  state now retains the original route. Evidence advancement and checkpoint
  writes require the assigned lane; coordinator and scout writes are rejected.
- **CA-16 / IMPORTANT / BEHAVIOR, fixed:** Delta assembly compared the old base tip
  instead of the dispatched baseline head. It now pins the exact baseline while
  permitting independent base advancement, rejects fresh findings outside the
  dispatched paths, and reopens recurring fixed findings with their existing ID.
- **CA-17 / IMPORTANT / BEHAVIOR, fixed:** Overlapping or delayed memory ingestions
  could replace newer outcomes and vectors. Indexed admission serializes work per
  repository, excludes embedding migration, skips obsolete entries before paid
  embedding, and rejects stale writes at the mutation boundary.
- **CA-18 / IMPORTANT / BEHAVIOR, fixed:** Lost ingestion actions could hold memory
  and deletion queues indefinitely. An attempt-bound watchdog releases abandoned
  work after 11 minutes, with bounded retries. Completion and retry mutations
  accept only active work, so a late error cannot revert a completed job.
- **CA-19 / IMPORTANT / BEHAVIOR, fixed:** Cleanup ignored command failure and left
  review evidence on disk. It removes workspace and application evidence, checks
  the exit code, and stops compute even when deletion or transport fails.
- **CA-20 / IMPORTANT / QUALITY, fixed:** The installed Gateway SDK marks response
  errors with HTTP 404 as nonretryable. Generation-record reconciliation now
  treats that delayed-record case as retryable, preserving existing attempt bounds.
- **CA-21 / IMPORTANT / BEHAVIOR, fixed:** Pagination rejected exactly 2,000 items
  despite documenting that bound. One empty-page lookahead now distinguishes the
  supported boundary from overflow; malformed oversized pages also fail.
- **CA-22 / IMPORTANT / BEHAVIOR, fixed:** Oversized staged reports raised a generic
  storage error, preserving the same unpublishable report on retry. Size checks
  now run before a GitHub request and produce validation diagnostics that clear
  the report so it can be corrected.

The canonical finding and lane-report shapes remain unchanged. Report execution
identity is now `review-report-v2`, with app-owned baseline and path scope.
Revalidation is the model-facing schema change. All variants, application-owned
fields, path constraints, duplicate identity behavior, and downstream assembly
are exercised offline; all four PR 61 replays retain their finding transitions.

The [official convex-test library](https://docs.convex.dev/testing/convex-test)
executes the real mutation handlers against its simulated database. Tests inspect
scheduled jobs without running embedding actions. The watchdog exceeds the
[Node action execution limit](https://docs.convex.dev/production/state/limits);

## Fifth pass: publication capacity, bounded downloads, and durable migrations

- **CA-32 / IMPORTANT / OPERATIONS, fixed:** A valid 2,000-file baseline could
  exceed GitHub's comment capacity and prevent publication. State now uses gzip
  when necessary, then immutable digest-addressed comment parts. All parts are
  saved before the summary pointer changes. Retrying an interrupted write reuses
  existing parts and preserves the previous complete baseline. Every comment is
  limited to 65,000 bytes, the serialized state to 8 MiB, and compressed storage
  to 64 parts of 60,000 characters. Individual oversized findings fail staging
  with a correctable validation error. Legacy single-comment state remains readable.
- **CA-33 / IMPORTANT / BEHAVIOR, fixed:** Checking only the bot author still
  admitted a state marker quoted inside a bot-published finding. State readers
  now require the application state envelope at the start of the comment.
  Attachment ownership and digest validation apply to every collected part.
- **CA-34 / IMPORTANT / QUALITY, fixed:** The presentation path regex repeatedly
  rescanned long plain words. A left boundary prevents that quadratic behavior.
  On a 65,000-character fixture, nine alternating samples measured medians of
  599.17 ms before and 0.51 ms after, with identical output. This measurement
  covers the formatter only, not total review latency.
- **CA-35 / IMPORTANT / OPERATIONS, fixed:** Artifact downloads buffered archives
  without a resource bound. Octokit's installed request implementation supports
  returning its response stream; collection now bounds each archive to 64 MiB
  and all archives to 256 MiB, verifies advertised size before requesting bytes,
  checks actual streamed bytes, cancels overflow, and sets a 60-second download
  deadline. Workflow head/repository identity is checked before downloading.
  Digest and provenance validation remain required. Exceeding a bound fails
  preparation explicitly; it never silently drops evidence.
- **CA-36 / IMPORTANT / BEHAVIOR, fixed:** Queued re-embedding continuations could
  apply an old cursor to a newer pending model, and an abandoned action could
  hold ingestion/deletion forever. Each page or retry now has a durable token
  tied to its repository record and generation, saved cursor, attempt, and claim
  time. Mutations admit one worker and reject stale writes or completions.
  An 11-minute expiry resumes the same page with a fresh token, or releases
  deletion. Old scheduled calls restart from page one under the new contract.
- **CA-37 / IMPORTANT / QUALITY, fixed:** Effective-patch fingerprints always
  included the head blob SHA, so unrelated base changes triggered another review.
  Complete textual diffs now ignore blob identity only when every hunk balances
  and their addition/deletion counts match GitHub's totals. Missing, truncated,
  or malformed patches retain blob identity. Source CR bytes remain significant.
  A real Git rebase fixture proves stable identity across different blob SHAs and
  shifted hunks; tests retain detection of truncated tails and actual edits.
  Inbound and publication now share the same file parser.

## Sixth pass: memory revocation, complete cleanup, and queue progress

- **CA-38 / IMPORTANT / BEHAVIOR, fixed:** Removing the final repository row also
  removed the ingestion barrier, so a delayed request could recreate deleted
  memory. A persistent access record now issues a receipt before the app checks
  the installation's current repository access. Removal invalidates earlier
  receipts, even before their first ingestion. Paged reconciliation covers access
  registrations and existing memory. Repository re-addition accepts a fresh
  receipt; a full uninstall blocks its installation ID, and a new installation
  first clears any old content. Native delivery IDs deduplicate replay, and
  delayed removal events recheck access before deleting a restored repository.
- **CA-39 / IMPORTANT / OPERATIONS, fixed:** A queued cleanup could outlive its
  repository record, and an abandoned action had no recovery path. Cleanup now
  binds to the exact document ID, checks that identity inside its data queries
  and mutations, and schedules a persistent 11-minute watchdog. An old worker
  cannot skip the writer drain for a later deletion or erase a replacement row.
- **CA-40 / IMPORTANT / BEHAVIOR, fixed:** Deletion visited only recorded vector
  rows. A crash between RAG insertion and application bookkeeping left orphan
  entries behind. The app now uses the installed component's namespace-version
  listing and synchronous namespace deletion APIs. Every namespace version and
  its entries are removed before application rows, including untracked vectors.
  This also removes the redundant per-vector cleanup implementation.
- **CA-41 / IMPORTANT / QUALITY, fixed:** Consecutive embedding configurations
  could keep switching namespaces before queued ingestions ran. A migration now
  waits for pending work on the active model, and those ingestions may run while
  the next migration is queued but unclaimed. An action-level test executes two
  overlapping migrations through the actual installed RAG component and proves
  that both ingestions finish without any provider request.
- **CA-42 / IMPROVEMENT / QUALITY, fixed:** The standalone usage summarizer and
  its types had no runtime consumers; only their own test used them. They were
  removed. Runtime usage accounting, Gateway reconciliation, and the documented
  offline budget-policy evaluator remain in their owning modules.
